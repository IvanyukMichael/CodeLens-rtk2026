## 1. Что это и где мы в проекте

CodeLens — RAG-система семантического поиска по Python-коду (Кейс 3, 2-й этап чемпионата
ГК «Ростелеком», дедлайн 24.06.2026). Вопрос на естественном языке (RU/EN) → top-5
релевантных фрагментов кода с подсветкой, релевантностью и chunk_id.

**Финальная конфигурация ретрива (заморожена):**
`bge-m3` + enriched (в базе) + HyDE-mix (α=0.5) на стороне запроса, HyDE `temperature=0`
(greedy, детерминирован), хранилище ChromaDB.

**Путь, который прошли** (headline — официальные 15; вся история — в [REPORT.md](REPORT.md)):

```
официальные 15:  MiniLM raw 0.700 → bge-m3 raw 0.656 → +enriched 0.767 → +HyDE-mix 0.800  ← ПРОД
combined-269:     MiniLM raw 0.601 → bge-m3 raw 0.838 → +enriched 0.833 → +HyDE-mix 0.890  (robustness)
```
HyDE — живой `temperature=0` (детерминирован по метрике); прежнее расхождение 0.822 (frozen temp=0.2)
снято. Всё считается на изолированной gymhero-коллекции (см. §5 п.6 / REPORT §2.5).

**Отклонено по данным** (парный бутстрап; вердикт — по официальным 15, мощность — по combined-269):

- **rerank** (cross-encoder) — «выигрыш» только на синтетике (combined-269 Δ=+0.084, но на
  официальных 15 Δ=**−0.022**, вредит); 23↑/0↓ на LLM-вопросах — артефакт переобучения кросс-энкодера
  на формулировки LLM. Модель 568M + латентность, надёжного выигрыша на человеческой метрике нет → не внедрён;
- **BM25-гибрид (RRF)** — оверфит тюнинга `w=0.2`: на официальных 15 (live temp=0) ниже dense
  (0.778 < 0.800), на combined-269 нейтрален (−0.009) → не внедрять;
- **multi-HyDE** (×3 сэмпла) — нулевой прирост vs single, 3× дороже → одиночный HyDE.

**Значимость:** HyDE-mix значим на combined-269 (Δ=+0.058, CI [+0.020, +0.095]) и положителен на
официальных 15 (+0.033) → принят. **Enrichment** — главный выигрыш на человеческой метрике
(официальные 15: +0.111), на синтетике размывается (−0.006); это и есть причина держать срезы на
человеческой разметке. ⚠️ Тот же синтетический набор инфлирует reranking и давит enrichment —
доказано per-subset bootstrap'ом (REPORT §3.4/§4), поэтому combined-269 — только агрегат-довесок.

| [enriched_chunks.py](enriched_chunks.py) | Тонкая обёртка-shim над `enrich.py`: re-export `build_enriched_map` (чтобы исторические импорты экспериментов не ломались) + CLI-дамп `cache/enriched_texts.json`. | можно дорабатывать |

  резолвится в msys2 без ML-зависимостей (см. §5).

## 4. Ключевые решения и почему так (чтобы команда не переоткрывала)

- **Чанк = функция/класс/метод.** Минимальная семантическая единица, AST-детерминизм,
  совпадает с гранулярностью вопроса. Калибровка 30/30 с эталоном — формат chunk_id точный.
- **Эмбеддим обогащённый текст, не голый код.** Enrichment — единственный статистически
  значимый прирост (CI [+0.012, +0.099], 6/0). Это фундамент, не трогать без переиндексации.
- **bge-m3 как эмбеддер:** лучший на bake-off (enriched 0.767 на 15-q), мультиязычный, код-aware.
  gte-Qwen2 провалился (0.278/0.344 — не код-tuned). e5-large — близкая альтернатива (0.733,
  силён на ru). MiniLM (baseline) — 0.700.
- **HyDE-mix закрывает «RU-вопрос ↔ EN-код»:** LLM генерит гипотетический код с английскими
  именами → мост между языком вопроса и языком кода. Чинит слабые срезы (hard, en). Принят как прод.
- **temp=0 для воспроизводимости:** run1≡run2 по метрике, без замороженных артефактов.
  `cache/hyde_query_cache.json` — обычный кэш ускорения (пишется из живых temp=0 генераций), не frozen-сид.
- **Негативный порог 60%** откалиброван по распределению top-1 relevance (негативы ≤58.4,
  истинный пол позитивов 62.8 — чистый зазор). Влияет только на UI-баннер, P@5 не трогает.
- **Отклонённые техники — это фича, не баг.** rerank / hybrid / multi-HyDE проверены и отклонены
  по данным (вердикт — на официальных 15, мощность — на combined-269) — материал для отчёта. Не
  возвращать без новых данных (rerank «выигрывает» только на синтетике; гибрид оверфит на 15-q).

## 5. Грабли (известные, задокументированы)

1. **`SSL_CERT_FILE` в Git Bash указывает на несуществующий cacert** → падает загрузка моделей HF
   (`FileNotFoundError` ещё до чтения локального кэша). Чинит [sslfix.py](sslfix.py) (импортируется
   первым). Глобально: `export SSL_CERT_FILE="$(python -c 'import certifi; print(certifi.where())')"`.
2. **MSYS2-python перехватывает shell.** Голый `python` может резолвиться в `C:\msys64\…` без
   ML-зависимостей. Запускать явно интерпретатором env `codelens`
   (`…/miniconda3/envs/codelens/python.exe`) или активировать env.
3. **gte-Qwen2 + transformers 5.x:** `trust_remote_code=True` падает (`'Qwen2Config' has no
   attribute 'rope_theta'` — remote-код предшествует RoPE-рефактору v5). Решение — нативный
   `Qwen2Model` (`trust_remote_code=False`). `transformers==5.11.0` запинен не случайно.
4. **0.822 (frozen) vs 0.800 (прод headline).** Заголовочные 0.822 на официальных 15 — это удачная
   выборка на frozen temp=0.2 генерациях. Живая генерация при любой температуре регрессирует к
   **0.800 (офиц.15)** — это и есть headline. Прод = live temp=0; 0.822 не цитируем как результат.
   (Исторический эксперимент на исходном 71-наборе давал там 0.831 — см. REPORT §6; теперь
   robustness считаем на combined-269 = 0.890. Старые temp=0.2-числа сохранены в `cache/` как база A/B.)
5. **Детерминизм не побайтовый.** 2 HyDE-генерации (`q_13`, `g_08`) расходятся в формулировках,
   но top-5 и P@5 идентичны между прогонами. Единственный строго нулевой по вариативности вариант —
   замороженный кэш; мы выбрали воспроизводимость по метрике, а не по байтам.
6. **Смешивание корпусов в ОДНОЙ коллекции ломает официальную метрику (cross-project dilution).**
   Если индексировать gymhero и доп-репозитории в одну коллекцию ChromaDB, доменно-близкие чанки
   из других проектов (особенно JS/Java-демо с тем же auth-доменом) вытесняют эталонные
   gymhero-ответы из топ-5: P@5 падает 0.800 → 0.656 на офиц.15. Пути gymhero при этом **не
   меняются** (chunk_id идентичны, калибровка 30/30 цела) — деградирует только ранжирование.
   **Решение (внедрено):** две изолированные коллекции `codelens_gymhero` / `codelens_extra`;
   `search.search(..., source="gymhero")` — область официальной метрики; `python index.py` жёстко
   маршрутизирует gymhero в свою коллекцию (затереть её distractor'ами нельзя). Подробно — REPORT
   §2.5 и замер по источникам. **Не индексировать доп-репо в gymhero-коллекцию.**
7. **Дубли в `eval_extended.json`: 254 записи, но 155 уникальных `question_id`** (99 дублей
   `g_57..g_155` повторены дважды — наложение волн генерации командой). Значит combined-269
   фактически ≈170 уникальных с двойным счётом → **ещё одна причина** держать combined только как
   robustness-агрегат, не headline. Официальных 15 и исходных 56 (`g_01..g_56`, уникальны) это **не
   касается** — headline и срезы считаем на них. Файл сейчас НЕ дедуплицируем (числа в REPORT уже
   посчитаны на нём, не сдвигаем задним числом) — **дедуп в backlog** (см. §6).

## 7. Принципы работы (как мы вели проект — стоит продолжить)

- **Каждое изменение метрики меряем на двух наборах: combined-269 (мощность) + официальные 15
  (знак истины), до/после, на `score.py`.** Не верим приростам на 15 в одиночку (1 вопрос = 0.067,
  шум) и не верим «победам» только на синтетике (артефакт). Так поймали оверфит гибрида и
  синтетический «выигрыш» реранка.
- **Отрицательный результат — это результат.** Если техника не помогла — документируем с числами
  и CI, это идёт в отчёт и усиливает защиту.
- **Воспроизводимость прежде красоты.** Кэшируем (cache/ в git), пинуем версии (requirements.txt),
  seed в бутстрапе. Прод не зависит от платного API-ключа.
- **Честность в числах.** Никаких подогнанных под демо порогов, никаких замороженных артефактов
  в проде, расхождения проговариваем явно (0.822 frozen → 0.800 headline; синтетика — только
  robustness-агрегат 0.890, не срезы).
- **Коммитим часто, осмысленными сообщениями** (история коммитов — часть оценки за чистоту репо).
